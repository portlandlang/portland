# 0045 — The def shapes: multiline, paren-less, endless

- **Status:** Accepted (built in both oracles, 2026-08-20)
- **Date:** 2026-08-20
- **Issue:** [#82](https://github.com/portlandlang/portland/issues/82)

## Context

Three `def` signature shapes were committed as musts and refused as parse errors: multiline parenthesized parameter lists, Seattle.rb-style paren-less parameters, and endless defs. The endless form had a pull twice over — the deciding user's standing Ruby style, and this compiler's own author reflexively writing one into `inference.pdx` and being refused by the parser being extended. Every design question was pre-answered: annotation placement by ADR 0041 (the arrow comment trails the line where the parameter list ends, every shape), and each edge by probing Ruby 4.0.6 and matching.

## Decision

All three ship, Ruby-parity throughout — twelve edges probed before building:

<!-- not-portland: sketches, bodies elided -->

```ruby
def add(first,
        second)          # newlines flow inside the parens

def greet name, punctuation   # paren-less, to the end of the line

def label kind,               # trailing comma continues the list,
          text                # Ruby's line-end reasoning

def answer = 42               # endless: one guarded statement, no end
def double(number) = number * 2
def cautious = "ran" if false # the body takes a postfix guard
```

1. **Inside parens, newlines flow** after the opener, after commas, and before the close. The leading-comma style (`bar\n, baz`) stays refused — one continuation shape, the trailing comma.
1. **The paren-less list ends where Ruby's would**: a line ending in a comma means more parameters; without one, the list is done. Defaults work (`def fallback bar = 9`), which is Ruby's own carve-out and why —
1. **Endless defs require parens around any parameters, and nothing enforces it** — it falls out: after a bare list, `=` was already a default. `def add a, b = a + b` means what it means in Ruby (a default), and then fails to find its body, exactly as Ruby refuses the same line.
1. **An endless body is one guarded statement** — command calls and postfix modifiers included (`def maybe = 1 if true` answers nil on the miss, ADR 0012's branchless-if), no `end`. Type functions ride: `def self.tau = 6` (`fields` stays `def self.new`-only, ADR 0031 unchanged).

## Consequences

- Non-difference from Ruby, whole: every accepted shape means what Ruby means, every probed refusal stays a refusal. The invented-syntax test loses its endless-method row; only the committed ternary (#83) remains on it.
- `inference.pdx`'s author-reflex line (`def numeric?(type) = ...`) would now parse — the pull that filed half this issue is satisfiable, though the source keeps its block form until a cleanup pass wants otherwise.
- The `# -> Type` annotation story (ADR 0041) needed no update: its placement rule was written for these shapes before they existed.
