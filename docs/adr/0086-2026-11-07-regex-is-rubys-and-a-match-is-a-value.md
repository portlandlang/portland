# 0086 — Regex is Ruby's, and a match is a value

- **Status:** Accepted (ruled by the deciding user 2026-11-07 on the recommendations in [#74](https://github.com/portlandlang/portland/issues/74), one question at a time; built on both implementations 2026-11-07. The engine is Onigmo ported to the seed, layer for layer from Ruby 4.0.9's own copy, agreeing with Ruby on all 1,075 cases of Onigmo's suite — [#212](https://github.com/portlandlang/portland/issues/212) records the evaluation of oniai that preceded it. The `o` flag's reading below is the author's and is open to amendment.)
- **Date:** 2026-11-07
- **Issue:** [#74](https://github.com/portlandlang/portland/issues/74)

## Context

Regex has been the standing hole since the docs restructure. The level-0 gem census ([#74](https://github.com/portlandlang/portland/issues/74)) made it the largest single refusal in the corpus: a regex literal is what stops roughly 30,000 gems at the lexer, and the only thing stopping about 2,600 of them. Inside ruby/spec it holds `sub`, `gsub`, `match`, `scan`, `=~`, `split` with a pattern, the whole of `core/regexp` and `core/matchdata`, the `%r` member of the `%` family ([ADR 0051](0051-2026-09-24-the-percent-literal-family.md)), and the replacement-string question [#161](https://github.com/portlandlang/portland/issues/161) parked on it.

Ruby's regex is Onigmo: backreferences, lookahead and lookbehind, named captures, atomic and possessive groups, subexpression calls, Unicode properties. Its match API leans on globals the language dropped with the rest of the runtime magic ([removed-syntax.md](../ruby/removed-syntax.md)): `=~` answers an index and sets `$~`, and `$1` reads the capture. And a Portland string counts graphemes ([ADR 0038](0038-2026-08-19-what-a-character-is.md)) where Ruby's engine counts codepoints, so a match's positions have to pick a unit.

## Decision

1. **Regex literals are Ruby's.** `/\d+/` with the `i`, `m`, and `x` flags, interpolation inside the literal, and `%r{...}` with the `%` family's delimiters ([ADR 0051](0051-2026-09-24-the-percent-literal-family.md)) — `%r` survives. `Regexp.new(text)` builds one from a string as a type function ([ADR 0058](0058-2026-10-16-builtin-types-carry-type-functions.md)), with `Regexp.escape` and `Regexp.union` beside it; `source`, `options`, `names`, and `to_s` read a regex back. The `o` flag — interpolate once, a caching trick — refuses by name with the rewrite "drop the flag"; the compiler can hoist a constant pattern itself.
1. **The pattern language is Onigmo's, whole.** Every construct Ruby's engine reads means the same here; a construct the engine has not built yet refuses by name, never silently matches differently. The engine is the seed's own port of Onigmo, `seed/src/regex/`, written layer for layer from Ruby 4.0.9's copy — the preprocessing of `re.c`, the parser of `regparse.c`, the compiler of `regcomp.c`, the matcher of `regexec.c`, the case folding and property tables of `enc/unicode` — and pinned against Onigmo's own 1,075-case suite with Ruby's answers as the ground truth, a ratchet in `script/test`. [#212](https://github.com/portlandlang/portland/issues/212) records the alternatives weighed: [oniai](https://github.com/makenowjust/oniai), a pure-Rust Onigmo, evaluated byte for byte against Ruby (unlicensed, one case in six differing, seventeen hangs) and used as a blueprint; and the `onig` bindings to Oniguruma's C, declined as a library outside the memory model that the Rust-or-Portland count could never retire. The surface over the engine, `seed/src/regexp.rs`, is the one boundary a program sees, and the hosted compiler reaches it through the seed, so the engine can change without a program noticing; the Stage 2 repayment is the same engine in Portland.
1. **A match is a value: `MatchData` or nil.** `text =~ /pattern/` and `text.match(/pattern/)` both answer the `MatchData` or nil — one behavior, two spellings ([ADR 0036](0036-2026-08-18-the-famous-twins-ship.md)) — so a match is a maybe and narrows by the seven forms of [ADR 0040](0040-2026-08-19-inference-the-design-core.md) §3; `match?` answers true or false; `!~` is `match?`'s negation. This changes `=~` from Ruby, whose index-or-nil is only useful beside `$~`: without the globals an index alone cannot reach the captures, and a Ruby spelling should not mean less here. `MatchData` is a struct with Ruby's reading API — `[0]`, `[1]`, `[:name]`, `captures`, `named_captures`, `names`, `pre_match`, `post_match`, `begin`, `end`, `offset`, `to_a`, `to_s`, `values_at` — rendering as Ruby's `#<MatchData "1984">`. `$~`, `$1`–`$9`, `` $` ``, `$'`, `$&`, and `Regexp.last_match` refuse by name with the rewrite: bind the match and read it. `when /pattern/` works by `===` as every `when` does ([#150](https://github.com/portlandlang/portland/issues/150)); `in /pattern/` with captures bound by name is the Portland-native home and builds when a port pulls for it.
1. **Positions are grapheme indices; characters are codepoints.** `begin`, `end`, `offset`, `pre_match`, `index(/x/)`, and every position a match answers count graphemes, translated at the boundary from the engine's byte offsets, so a position a match answers is one `slice` accepts. Inside the pattern the engine keeps Onigmo's characters: `.`, a negated class, and `\p{L}` match one codepoint, and `\X` is the one grapheme-matching escape. A grapheme-aware character class is a research question, not a ruling; the rows where a combining mark splits the two are recorded differences in the ledger.
1. **Replacement strings keep Ruby's escapes** ([#161](https://github.com/portlandlang/portland/issues/161)'s option 1): `\0` and `\&` the match, `\1`–`\9` a group, `\k<name>` a named group, `` \` `` and `\'` the text before and after, `\\` a backslash, any other `\x` as written; `"2026-11-07".sub(/(\d+)-(\d+)-(\d+)/, '\3/\2/\1')` is `"07/11/2026"`. The block form receives the matched text as a String, as Ruby's does — `gsub(/\w+/) { |word| word.capitalize }` ports unchanged — and a block that needs the captures uses the escapes or a `match` loop, since `$1` refuses.
1. **The string methods take a regex wherever Ruby's do**: `sub`, `gsub`, `scan`, `split`, `match`, `match?`, `index`, `rindex`, `slice`, `[]`, `start_with?`, `partition`, and `rpartition`, with `Symbol#match` and `Symbol#match?` beside them. The ruby/spec files are the specification; tie goes to Ruby. What those pages already decided stands: the bang forms follow [mutability.md](../ruby/mutability.md), and `count`'s character sets stay refused ([string-count.md](../ruby/string-count.md)).

## Consequences

- Both lexers learn the literal: `/` in operand position opens a regex, in operator position stays division, with Ruby's own disambiguation (a space before and none after, as `puts /x/` versus `a / b`); the backslash-continues-a-line refusal that today hides regex literals in the census goes away for them.
- Both implementations gain a `Regexp` value, a `MatchData` struct, the type functions, the regex-taking arities of the string methods, and the replacement-escape reader; the builtin method table in `compiler/inference.pdx` gains the two receivers, reprobed by `script/probe_builtin_methods`.
- `core/regexp` (24 files), `core/matchdata` (30), the regex rows of `core/string`, `core/symbol`, `core/kernel`, and `language/regexp` port once the engine is ruled; the 15 manifest rows and 51 skipped reasons that cite [#74](https://github.com/portlandlang/portland/issues/74) move to the build.
- Ledger: a new [regex.md](../ruby/regex.md); [percent-literals.md](../ruby/percent-literals.md) moves `%r` from deferred to decided; [characters.md](../ruby/characters.md) gains the position rule. [#161](https://github.com/portlandlang/portland/issues/161) closes as decided here.
