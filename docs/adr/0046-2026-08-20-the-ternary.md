# 0046 — The ternary: declared spacing, nesting refuses toward parens

- **Status:** Accepted (built in both oracles, 2026-08-20)
- **Date:** 2026-08-20
- **Issue:** [#83](https://github.com/portlandlang/portland/issues/83)

## Context

The commitment was ruled 2026-08-19 (#83): ternaries are common, useful, beloved Ruby, and "Portland won't have ternaries" was not a defensible position. The build waited on the collision design — `?` already ends predicate names and `:` already spells symbols and labels, and Ruby threads that needle with whitespace heuristics and lexer state nobody can recite. ADR 0033's counter-principle applies instead: **a declared grammar rule is one reading, not two.** Two rulings arrived pre-answered from the quest launch: the spacing is strict, and nesting refuses toward parens (the deciding user's choice from the presented field).

## Decision

**`cond ? yes : no` is legal Portland, desugared at parse to the same If node as its wordy twin `if cond then yes else no end` (ADR 0042).** No new AST, zero evaluator surface, in both oracles. The rules, each declared rather than guessed:

1. **A spaced `?` is the ternary; an attached `?` ends a name.** The lexer keeps `ready?` whole exactly as before; a `?` standing alone becomes the new Question token. `found.nil? ? 0 : 1` reads both apart. Likewise **an attached `:` makes a symbol or a label; the ternary's `:` is spaced** — so `a ? :x : :y` parses, each colon meaning what its spacing says.
1. **Precedence sits below range, above `in`** — probed on Ruby 4.0.6 and matched: `a || b ? c : d` conditions on the whole `||`, `true ? 1..2 : 3..4` takes range operands, `x = cond ? a : b` assigns the answer.
1. **Nesting refuses toward parens.** Operands parse one notch below the ternary itself, so `a ? b : c ? d : e` cannot form; the refusal names the rewrite — `a ? b : (c ? d : e)`, which is legal. This is a deliberate divergence from Ruby's right-associativity: the migrating line refuses loudly with its own spelling in the message, never silently reads differently.
1. **The half-spaced forms refuse with menus**, byte-identical on both oracles and pinned:
   - `a ?b : c` — `a ternary spaces its ? on both sides — an attached ? ends a name like ready?` (Ruby 4.0.6 parses this one as a ternary; Portland is stricter by declaration)
   - `a ? b: c` and `a ? b :c` — `a ternary spaces its : on both sides — an attached : makes a symbol like :ready` (the second lexes `:c` as a symbol, which is exactly the collision the wording explains)
   - `a ? b` — `a ternary needs its else — write cond ? yes : no`
   - the nesting refusal above — `ternaries do not nest — parenthesize the inner one: a ? b : (c ? d : e)`

Two edges stay organic rather than designed. `a? b : c` has one reading under the declared rules — `a?` is a name — so it fails as a malformed statement with the generic boundary wording, not a menu. And Ruby's `(1..3) ? a : b` is a flip-flop, which Portland never had; here the range simply reaches the If node and refuses as a non-boolean condition at runtime.

## Consequences

- The invented-syntax test retires with its last row: all three forms docs/language.md once wrote from memory (one-line if, endless defs, the ternary) became real.
- language.md's "committed but unbuilt" paragraph flips to built; the one-line `if a then b else c end` stops being the interim spelling and becomes what it always was underneath — the same node.
- superset.md is untouched: every accepted ternary spelling is Ruby-parity, and the divergences are refusals, which is the migration promise working.
- `&.` and `?`-suffix names are unaffected; no program that lexed before this ADR lexes differently after it.
