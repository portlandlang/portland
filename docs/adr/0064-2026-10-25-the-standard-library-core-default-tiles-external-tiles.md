# 0064 — The standard library: a core, default tiles, and external tiles

- **Status:** Accepted (ruled by the deciding user 2026-10-25 in discussion on [#78](https://github.com/portlandlang/portland/issues/78); nothing built — the build is [#176](https://github.com/portlandlang/portland/issues/176), the package system is [#174](https://github.com/portlandlang/portland/issues/174))
- **Date:** 2026-10-25
- **Issue:** [#78](https://github.com/portlandlang/portland/issues/78)

## Context

The ruby/spec import ([#23](https://github.com/portlandlang/portland/issues/23)) left `library/` untouched and the OS areas — `core/io`, `file`, `dir`, `env`, `process`, `signal`, `time`, `random`, about 3,500 examples — unimported, because Portland had no standard library story: a silence, not a decision. The whole OS surface today is four builtins, `read_file`, `write_file`, `argv`, and `puts`, which is exactly what the compiler needed and nothing more.

Two facts shaped the ruling. First, ruby_research's level-2 census (dependency closure, `6f9292d`): of the 10,426 gems whose `lib/` parses, 3,131 are held back only by a dependency that does not, and the top of that list is Ruby's own former standard library — `logger` (1,574 gems), `base64` (1,373), `bigdecimal` (1,043), `json` (839), `benchmark` (705), `securerandom` (689). Second, why they are at the top: Ruby's standard library is three tiers now — core, default gems, bundled gems — and has spent a decade moving libraries outward. `base64`, `csv`, and `bigdecimal` left the default set in 3.4; `logger`, `benchmark`, and `ostruct` in 4.0; `tsort` leaves in 4.1. Every gem that called one had to add it as a dependency, so the census ranking is in large part a measurement of Ruby's own retreat. "Stdlib" in Ruby conversation names a cultural category — the libraries that came with Ruby when the speaker learned it — not a technical one.

The deciding user prefers Ruby's current shape to its 1.8 one: standard-library things are packages, and some arrive installed with the language.

## Decision

1. **Three tiers: core, default tiles, external tiles.** A *tile* is a Portland package (the working name; composable pieces, stackable blocks, the PDX airport carpet). **Core** needs no `require`, ships inside `pdx`, and is versioned with the language: the builtin types, and whatever Ruby made core — `Set` ([#123](https://github.com/portlandlang/portland/issues/123)), `Math` ([#126](https://github.com/portlandlang/portland/issues/126)), `Random` ([#169](https://github.com/portlandlang/portland/issues/169)), `Time`. A **default tile** is installed beside `pdx`, loads by `require "name"` with no manifest line, and is a real package with its own version and repo, upgradable without upgrading the language. An **external tile** is declared in the manifest and installed. There is no monolithic standard-library directory in this repo.
1. **No bundled tier.** Ruby's bundled gems — in the tarball, invisible to Bundler without a Gemfile line — are the halfway house of a migration Ruby had to make gently. Portland has nothing to migrate, so the tier that produces "`csv` was loaded from the standard library, but is not part of the default gems" does not exist here.
1. **The floor is coarse.** A floor primitive is one named operation that crosses into the runtime once and may make several syscalls — `read_file`'s shape: open, read to the end, close, one string back. The fine model — `open` returning a handle, `read` in chunks, `close`, with `File.read` written in Portland over them — is what streaming a file larger than memory needs, and it brings a resource with a lifetime into the language. It is parked, not refused, for the pull that needs it; [ADR 0055](0055-2026-09-25-no-lazy-tier-yet.md)'s infinite walk rides with it. The primitives are the floor's names, not user API, and live under one module name so every crossing is greppable, as `mutable` and `panic` are.
1. **Core exposes five primitives for the first wave:** a wall clock (`clock_gettime` with `CLOCK_REALTIME`), a monotonic clock (`CLOCK_MONOTONIC`), entropy (`getentropy(2)`), a write to stderr, and a file append. `Time` is a struct in Portland over the wall clock; *core* means it ships inside `pdx` and needs no require, not that it is written in Rust.
1. **JSON is a loan.** Rust's `std` has no JSON and Apple's public SDK has none in C — `CFPropertyList` reads plists only, and `plutil`'s JSON goes through Foundation's `NSJSONSerialization`, Objective-C. The seed takes `serde_json` as its second dependency behind two primitives, parse and generate, and the `json` tile is Portland over them. Stage 2 repays the loan — a JSON parser in Portland, or a ruling then that the permanent floor may hold one — and this ADR does not pretend the choice is free. Two decisions live in the mapping and are not serde's: what JSON `null` becomes under typed absence ([ADR 0005](0005-2026-07-22-optionals-wrapper-model.md)), and that `JSON.parse` answers string keys unless asked otherwise, as Ruby's does.
1. **The first five default tiles, in the census's order:** `json`, `base64`, `logger`, `securerandom`, `benchmark`. Each is Portland over core, spelled as Ruby spells it (principle 2), landing with its tests. In MRI every one is a Ruby file over C — `base64.rb` is six calls to `Array#pack("m")`, `SecureRandom` sits on `Random.urandom`, `json` dropped its pure-Ruby parser in 2.8 — so the port writes the C half in Portland, and `base64` pulls the bytes question ([#119](https://github.com/portlandlang/portland/issues/119)) before it pulls anything from the floor. Beyond the five, nothing is scheduled; the next pull names the next tile.
1. **Declined by doctrine:** `ostruct` (`method_missing`), `delegate`, `forwardable`, `singleton`, `observer`, `weakref`, `monitor` (an open runtime, or shared mutable state), `thread`, `timeout` (`together`, [ADR 0029](0029-2026-07-27-together-semantics.md); timeouts are its tier three), `English` (globals), `pp` (`p` and `inspect`). `bigdecimal` stays [#124](https://github.com/portlandlang/portland/issues/124)'s. Shell execution — backticks, `system`, `spawn`, `popen`, `fork` — is **not decided here**: [ADR 0051](0051-2026-09-24-the-percent-literal-family.md) declined `%x` as a literal and deferred the spawn itself to this issue, which did not reach it; it is [#179](https://github.com/portlandlang/portland/issues/179)'s. (An earlier wording of this sentence misread 0051 as having declined shell execution outright; corrected the same day.)
1. **Deferred to their own issues.** The package system — the manifest's name and shape, the `require` spelling for a tile, how a default tile installs and upgrades — is [#174](https://github.com/portlandlang/portland/issues/174), and until it is decided a standard-library name in `require` refuses as [#116](https://github.com/portlandlang/portland/issues/116) proposes. `argv()` becoming `ARGV` under [ADR 0053](0053-2026-09-24-constants.md) waits for the OS wrappers.

## Consequences

- The OS half of ruby/spec has a port rule: `core/io`, `file`, `dir`, `env`, `time`, `process` port against the Portland wrappers as each lands. The rows that cannot are sorted three ways, none decided here: rows a decided ADR rules out — `IO::Buffer`, signals, `ARGF` — are proposed never-port in [#175](https://github.com/portlandlang/portland/issues/175); the spawn rows wait on [#179](https://github.com/portlandlang/portland/issues/179); rows that need a handle value wait on the parked fine model in [#177](https://github.com/portlandlang/portland/issues/177); permission bits, `File::Stat`, and the rest are plain unpulled, listed in [#178](https://github.com/portlandlang/portland/issues/178).
- The builtin method table in `compiler/inference.pdx` grows by the five primitives and no more; the wrappers are Portland and need no table. Its retirement, promised for "when the stdlib becomes Portland source", is now "when the default tiles are".
- `logger` to a file is one append crossing per line — open, write, close — which is correct and slower than a held handle. That is the coarse floor's cost, accepted until the fine model is pulled.
- The stance is recorded as a stance: Portland is choosing the shape Ruby arrived at by walking away from batteries-included, and the reasons Ruby left — a module nobody wants still ships, a module that needs its own cadence is chained to the language's — are the reasons a tile has its own version. Demand-driven admission keeps the default set short.
