# 0023 — Symbols: a general type, checked against declared vocabularies

- **Status:** Accepted (built in the seed, 2026-07-25; the trio waits)
- **Date:** 2026-07-25

## Context

Symbols were audited on 2026-07-23 and deliberately tabled ([session notes](../history/2026-07-23-symbols-first-pass.md)). The core question was answered that day; what blocked the ADR was the enum shape symbols lean on, which [ADR 0022](0022-2026-07-25-enums-with-payloads.md) has now settled. This records the decision rather than making it.

The audit's finding was that Portland's existing ADRs had already reassigned nearly every job Ruby's symbols do:

| symbol's job in Ruby | where it went |
|---|---|
| kwarg labels — `foo(name: "x")` | ADR 0014: compile-time labels, no symbol |
| struct-pattern labels — `in Token(kind:)` | ADR 0013: compile-time |
| `send`, `respond_to?`, `define_method`, `attr_accessor` | dropped forever — runtime metaprogramming |
| `&:upcase` | ADR 0017: `{ it.upcase }` covers it |
| **enum-ish values — `status = :pending`** | **unsolved, until 0022** |

Both of Ruby's *reasons* for having symbols are dead here. They are the interpreter's identifier table exposed as values — a bare Ruby 4.0.6 interns 3,599 symbols before user code runs, which is why symbols and metaprogramming are inseparable there — and Portland has no runtime method table. And interning works around mutable strings, which ADR 0015 already made immutable.

What survives is the semantic one: a symbol says **"this is a name, not data."** `"pending"` is text that might be user input, displayed, concatenated; `:pending` is an identifier from a vocabulary the program controls. That is the use–mention distinction, and it is what the affection is actually for.

**The reframe that unlocked it.** The session opened by asking whether "typed" precluded symbol *syntax*. It does not. Ruby's problem with `status = :pending` was never the spelling — it is that **the set is open**, so `:pendign` is a perfectly valid symbol that simply never matches. Declaring the set fixes that without touching the spelling.

## Decision

**`:foo` is an ordinary symbol literal and a general type. Where a declared closed vocabulary is expected, membership is checked; everywhere else a symbol is just a value.**

```ruby
purchase.with(status: :paid)          # checked against Purchase::Status (ADR 0022)
purchase.with(status: :pendign)       # compile error — not a case of that enum

config = {name: "pdx", port: 8080}    # symbol-keyed, Ruby-verbatim
config[:name]                         # works
config["name"]                        # compile error — a String is not a Symbol
```

### 1. Hash shorthand is symbol-keyed, and it ships

`{name: "pdx"}` means what it means in Ruby: symbol keys. This is table stakes — it is the most common modern Ruby hash form and is currently a parse error, which every arriving Rubyist meets in their first ten minutes.

String keys keep the rocket: `{"name" => "pdx"}` is unchanged and still works.

**`{:name => "pdx"}` is a compile error naming the shorthand.** It is a second spelling of a sentence the language already says, which is the same subtraction ADR 0020 made for heredocs. The migration cost is nil: RuboCop's `Style/HashSyntax` already defaults to enforcing the shorthand, so conforming Ruby already complies, and the rewrite is a free-tier autocorrect.

The rocket survives for keys the shorthand cannot express — `{:"odd key" => 1}` — and for any non-symbol key.

### 2. The literal forms are `:name` and `:"quoted"`

`:snake_case`, with an optional `?` or `!` suffix, since those are part of a name (`:paid?`). And `:"anything at all"` for keys that are not identifier-shaped.

**Operator symbols are out** — `:+`, `:[]`, `:<=>`. Their entire job in Ruby is `send`, `define_method`, and `&:`, all three of which Portland has already dropped. There is nothing left for them to do.

**Interpolated symbols are out** — `:"prefix_#{name}"`. Same reasoning, and see §3.

### 3. There is no `to_sym`

`Symbol#to_s` exists. `String#to_sym` does not.

This is the load-bearing omission. A symbol built from a string at runtime cannot be checked against any vocabulary, because the compiler cannot see it. Cutting `to_sym` means **every symbol in a Portland program is written literally**, which is precisely what makes membership checking possible at all rather than best-effort. It also closes the last door back to dynamic name construction, which is the metaprogramming Portland removed.

Erlang's atom table is the cautionary case: atoms are never garbage collected, so runtime atom creation is a denial-of-service vector.

### 4. Symbols compare by equality, and do not order

`:paid == :paid` is true; `:paid == "paid"` is a compile error rather than Ruby's silent `false`. Ordering is not defined — Portland orders integers only today, and a sorted vocabulary has no obvious meaning. Deferred until something asks.

## Consequences

- **Hash shorthand is unblocked**, and with it the enum work in ADR 0022, since enum cases are symbols. All three land together: `:foo` must lex before either of the others can exist.
- **Two string-like types now exist**, `String` and `Symbol`, which is the Ruby wart the session opened by trying to avoid. It is *mitigated, not eliminated*: a static type turns the classic mismatch into a compile error rather than Ruby's silent nil, so `HashWithIndifferentAccess` has nothing left to paper over. The choice still exists at every hash-key site.
- **Open positions stay unchecked.** A symbol where no vocabulary is declared is not checked: `config[:nmae]` is a valid symbol that simply misses, yielding a maybe per ADR 0010. The uncheckedness sits exactly where Ruby is also unchecked, and 0010 already forces the miss to be handled — but a typo there is not a compile error. A later lint could recover the common case, where a hash literal's keys are statically visible; recorded as direction, not decision.
- **Rails' indifferent access does not port.** Writing a symbol key and reading a string one becomes a compile error. Loud and mechanically fixable, but real migration work for Rails-shaped code.
- **The "one job per type" purity is given up**, deliberately. Symbols now do two things — enum case spelling and hash keys — which is less pure and more Ruby.
- **Rejected alternative:** symbols existing *only* as enum members, which buys total checking at the cost of `{name: "x"}` meaning string keys. The hash form is worth more.
- **Whether an enum case is assignable where a plain symbol is expected** is a widening question that belongs to inference (#9), not here. The seed cannot answer it: it is dynamically checked, so both are simply symbol values there.
- **Evidence caveat.** The corpus figure behind "symbols are beloved" — `symbol_node` in 80.6% of 500 gems, 208,911 occurrences — counts every use undifferentiated, and the audit above shows most of those uses are jobs Portland reassigned. The residue query that would size the enum-shaped usage has not been run; a full-corpus re-run is in flight. A prior, in ADR 0019's sense.
